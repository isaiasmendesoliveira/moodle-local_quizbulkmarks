# Contributing

Contributions are welcome.

## Development process

1. Fork the public repository.
2. Create a topic branch.
3. Keep all code, identifiers, and code comments in English.
4. Follow the Moodle coding style.
5. Add or update tests for functional changes.
6. Run Moodle Plugin CI before opening a pull request.
7. Open a pull request with a clear description of the problem and solution.

## Bug reports

Use the public issue tracker once the GitHub repository is created. Include:

- Moodle version;
- PHP version;
- database engine;
- theme;
- exact reproduction steps;
- expected and actual behaviour;
- relevant debugging output.

Do not disclose security vulnerabilities in public issues. See [SECURITY.md](SECURITY.md).
